# Бриф для kit-builder: кит `epic`

Это вход для сессии kit-builder в репозитории `ladohq/kit-epic`, в режиме «у меня уже есть процесс». Процесс шёл руками 5 дней (2026-10-14…18) на эпике «установка LADO через Docker» в `ladohq/lado`. Полный материал — `journal/docker-install.md` того же репозитория: 12 шагов, 2 релиза, 23 наблюдения. Читать его целиком.

Задача трекера: **LAD-103** (Yougile, доска Development). Настройки трекера — `.lado/tracker.yaml` этого репозитория.

## Что делает кит

Ведёт эпик от исследования до конца. Порядок такой:
1. План из маленьких проверяемых шагов.
2. Шаги по очереди. Каждый шаг — задача трекера, её делает кит `sdlc` (flow `task`).
3. После каждого шага — разбор итогов и пересмотр плана.

Кит не пишет код продукта и не повторяет `sdlc`, он его использует.

## Процесс, как он сложился

1. **Исследование** — отдельная задача sdlc. Результат — документ с проверками и трудностями.
2. **Ревью исследования и план.** Ревью ищет пробелы и противоречия. У каждого шага плана есть проверка. Человек принимает решения по открытым вопросам, они записываются в таблицу «Decisions taken».
3. **Правила ведения** (решения человека): план лежит в репозитории продукта. В трекере только очередная задача. Ветки эпика нет, всё идёт в `main`.
4. **Шаг:** черновик задачи → «да» человека → задача в трекере → бриф → «Start session» → `start_session` → сессия sdlc проходит flow `task`.
5. **Разбор шага.** Источники фиксированы, таблица в журнале:
   - Out of scope в предложении openspec;
   - «Not checked» и отклонённые находки в ledger;
   - комментарий интегратора;
   - `lado log` сессии: переписка с человеком и хвосты супервизора;
   - артефакты сессии;
   - `git log main` с прошлого разбора.
6. **Пересмотр плана** через PR, который супервизор эпика вливает сам после зелёного CI. Приёмы правки — наблюдение 3 журнала.
7. **Журнал эпика** (материал для улучшения кита) — по желанию.

## Точки человека

Решения по исследованию и плану, «создать задачу», «запустить сессию», гейты дизайна и слияния (внутри sdlc), ручная проверка, выбор порядка шагов и релиза. Всё остальное автоматизируется.

## Правила человека, которые обязательно в брифах шагов

- Ручная проверка — сразу шаги в PR (ветка, папка, команды, ожидаемое), с `env | grep` и `unset`.
- Граница шага: на каждом расширении спрашивать «это шаг или новая задача?».
- Задачи, родившиеся в шаге, сессия заводит сама по «да» человека, со связью derived.
- План и журнал ведёт эпик, сессия шага их не трогает.
- В конце сессия называет хвосты.
- На долгих шагах — короткие отчёты о ходе.
- Отказ на гейте со ссылкой на рекомендацию передаётся работнику целиком.
- Никаких глобальных разрушительных команд на машине человека.
- Основную копию человека не переключать: правки только в worktree.

## Что не сработало и должно быть в ките с начала

- **Файл состояния эпика.** Его читают при каждом старте и возобновлении сами, без ссылки от человека (наблюдения 13, 15, 20).
- **Конец сессии шага не виден эпику:** человек пишет «слито» руками (наблюдения 4, 22).
- **Эпик не видит соседние изменения продукта** (наблюдение 21).
- **Проверка, отложенная на релиз:** плану нужен статус «сделан, проверка открыта до X» (наблюдения 9, 14, 18, 19).
- **Совет, который человек не взял:** риск переходит в проверки релиза (наблюдение 23).

## Открытые вопросы дизайна (решает человек на интервью)

1. **Шаг — отдельная сессия (как сейчас) или прогон flow `task` в сессии эпика?** Сессия: свой контекст, параллельность, но нет обратного канала. Прогон: конец виден сразу, но один супервизор ведёт всё и быстрее теряет контекст.
2. **Как кит сочетается с sdlc.** Варианты: зависимость; две кита в одной сессии (`--kit sdlc --kit epic`, тогда при двух супервизорах ведёт встроенный); эпик только запускает сессии sdlc.
3. **Где план:** файл в репозитории продукта с PR на каждую правку, или артефакт и журнал вне продукта.
4. **Нужны ли изменения LADO:** уведомление родительской сессии о конце дочерней; `start_session` в другом репозитории. Это задачи `ladohq/lado`, не кита.
5. **Трекер:** через кит-трекер, как sdlc (`tracker`), с ветками эпика или без.
